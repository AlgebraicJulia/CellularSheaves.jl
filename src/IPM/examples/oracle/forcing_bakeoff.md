# Forcing-rule bakeoff (oracle, IPM)

Oracle sweep (`fix_alpha`, best-α per iteration) at `feas_tol = gap_tol = 1e-10`, δ=0.05 for
gnorm. `fac` = factorizations (= IPM iterations, the dominant cost); `slv` = Σ F⁻¹ applications
(the solve-side cleanup). Generated by `oracle_forcing.jl` (which only prints; this file is the
saved copy).

## Policies
- **abs** — absolute μ-schedule, `force_tol = min(0.1·μ/μ₁, 0.3)` (the current default).
- **V** (vartol) — relative `η·R0`, `η = max(0.01·feas_tol, min(1e-3·μ/μ₁, 1e-3))`, per-instance R0.
- **gN** (gnorm) — `force_tol = δ·pres` (i.e. `‖g−BΔp‖ ≤ δ‖g‖`, g = rp), δ = 0.05.
- **fix** (fixtol) — solve to a fixed target every iteration; here **target = feas_tol (1e-10)**.

## Findings
- **FAILs / 6:** absolute **0**; vartol / gnorm / fixtol all **1** — and every failure is **07**,
  the universal holdout that only absolute survives (by grinding 24 iterations at low α).
- **absolute is the only zero-fail policy**, and best on the two hard problems (07, e13).
- **fixtol(feas_tol) is the strongest challenger:** ties or beats absolute on factorizations for
  e01/e02/e04/e11 (e02 6 vs 8, e11 14 vs 16), loses only e13 (18 vs 17), and converges e01 where
  vartol/gnorm only reach NEAR_OPTIMAL. Cost: ~1.5–2× more inner solves.
- **fixtol tuning:** floor (≈2e-14) → tripped the `atfloor` guard (`force_tol=0` can never be
  REACHED_FORCE); 1e-8 → too loose, stalled above feas_tol and FAILed e11/e13; **feas_tol (1e-10) is
  the sweet spot** — the accuracy the IPM actually needs.
- **gnorm/vartol** win e02/e11 factorizations but are less robust (NEAR_OPTIMAL on e01).

Open: understand **07**, the one problem where every relative/fixed rule dies at fac≈8 while
absolute converges in 24. Cracking it would give a policy that dominates absolute on the dominant cost.
